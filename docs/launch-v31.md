## Public enrollment, binding and endowment transfer

1. Anyone calls `GameRegistry.register(role, actualLaunchNumber, index, exactCreationCode)` for each module. Roles 0..5 correspond to launch A indices 2..7; roles 6..9 correspond to launch B indices 0..3. `exactCreationCode` is the compiled creation bytecode *without* constructor arguments; the registry appends its own address. Verify all ten `Registered` events, `registered()==10`, all module getters and source hashes. The registry rejects wrong bytecode, wrong role, wrong constructor, missing deployments and any replacement. There is no privileged registrar.
2. The fixed team calls `V4Market.bindFeeRouter(actualFeeRouter)`. It is callable once by that address, checks the router's token/hook/Params wiring, and cannot be reset. The team must verify the full immutable graph before signing: this binding is an explicit one-time trust assumption, not an upgrade mechanism. Anyone then calls `flushFees()` to credit the existing held streams into the router.
3. **Immediately after the game is deployed**, the team publicly transfers the full token remainder into `RewardPool`. Preferred two-transaction route: token `approve(RewardPool, exactEndowment)`, then `RewardPool.fundEndowment()`. This pulls exactly the immutable principal and emits `Endowed(caller,amount,start,period)`. Equally supported: token `transfer(RewardPool, exactEndowment)`, then anyone calls `activateEndowment()`. Publish the transfer hash and activation event. Neither action creates donor, owner, recovery or withdrawal rights. Do not treat a transfer without activation as a completed step.
4. Before activation the whole promised principal is excluded from available funds, even if it arrives as a plain transfer. At activation the current bounded drip period is frozen for that endowment. Afterward available principal grows linearly from zero; later Params changes cannot accelerate it. Only FarmRewards can reserve released tokens and pay players under ordinary mining/claim accounting. The team retains a pre-transfer custody responsibility which the token launch cannot cryptographically eliminate using a plain remainder address. If it fails to transfer, the endowment is unfunded; report that publicly, rather than pretending a promise is available capital.
5. Allow 31 minutes of valid hook observations before using the 30-minute TWAP. Permissionless keepers start/advance epochs without farm work; preserve future entropy promptly, resolve purchases and finalize seasons. Farm owners or voluntary sponsors settle their own stale epochs in chunks of 1–8. Advance never waits for these transactions. Verify funding and the endowment event before soliciting game purchases. The starter window remains token-launch hour 48 through day 16; finish both application launches and enrollment in time. A delayed application deployment does not extend that v3 window.

## Heartbeat and operational responsibility

The retained v3.1 cost evidence prices IMD schedules at 0.5 IMD per run. [Capabilities checked by that job](https://api.imd.fun/requests/capabilities) quote schedule creation/top-ups on Ethereum chain 1. That evidence records the Robinhood on-chain intake as supporting oracle requests, but not schedule top-ups. Reconfirm these external capabilities before an authorized launch. A contract cannot use the available intake to buy heartbeat runs from this router's ETH; it also has no bridge/swap/HTTP-signing path. The router deliberately has no administrative withdrawal from `heartbeatBalance`.

A payer buys 140 runs for a 35-day, four-runs-per-day policy schedule: 70 IMD. At the observed 0.003451 ETH/IMD valuation this is 0.24157 ETH, **plus** mainnet acquisition/payment gas, slippage and any bridging by the payer. The quote is illustrative, not guaranteed. Any wallet may add runs via the documented `schedule.topup` quote/payment flow. Record payer, schedule ID, runs remaining and payment receipt publicly. The team can pay from its own withdrawn fee revenue, reducing net team proceeds by that actual cost. Nothing is silently deducted from the locked heartbeat ledger. The bootstrap payer must supply the first runs and transaction gas; token endowment alone does not pay them.

A six-hour IMD schedule is policy/research cadence, not a fast execution service. Public bots must independently monitor native block targets and all pending work. They need gas float, recover credited bounties using `FeeRouter.withdraw()`, and must check profitability and heartbeat funds. No EVM contract executes itself with literally no transactions. Permissionless incentivized work removes reliance on an online team, but cannot promise a willing bot when its balance is exhausted, gas rises above caps, or entropy capture is late.
